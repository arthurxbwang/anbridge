# 首版验证记录

日期：2026-11-09，Asia/Shanghai。

## 环境

- Debian 13，Linux amd64。
- Go 1.24.4：早期源码的首轮测试通过；最终模块要求 Go 1.27，
  不再以旧工具链作为受支持的构建方式。
- Go 1.27.3：最终代码的 vet、单元测试、race、真实 Nginx 集成测试与编译通过；
  分发二进制使用此工具链。
- 独立 Nginx 1.26.3，Debian 软件包版本 `1.26.3-3+deb13u10`。
- Go 1.27.3 从 Debian trixie-backports 解包，Release 用系统 Debian archive keyring
  验证签名，索引和包逐级核对 SHA-256。未添加系统 APT 源或安装软件包。
- Nginx 按已有 APT 元数据的 SHA-256 校验后解包到项目 `.tools`。

所有构建工具、输出及测试临时配置位于 `/root/anbridge`。
没有安装生产 systemd 单元，没有修改宿主机 Nginx 配置，没有连接真实业务站点。
测试只在临时回环端口启动独立 Nginx，并在完成后退出。

## 执行命令

```bash
make check
make test
make integration
make build
make units
./bin/anbridge check-config -config configs/anbridge.example.json
```

`make test` 会跳过未显式启用的真实 Nginx 测试。
本次另执行了 `make integration`，确认该测试实际运行而非跳过。

`make units` 使用项目内临时副本、当前构建二进制和占位 Nginx 依赖，
通过 `systemd-analyze verify` 检查单元语法及关系。它不启动真实服务，
不能代替目标 VM 上的用户、路径、权限、隔离策略和服务启动验证。

## 自动化测试覆盖

### 接收协议与权限

- AllinSSL 参考请求的认证头、上传格式、数值型 ID 和字符串 `msg`。
- 未认证请求拒绝；每站点独立 Token。
- 不能用其他站点的 Token 绑定暂存 ID。
- 上传不激活，绑定才调用部署帮助进程。
- 接收器重新实例化后可以继续绑定已持久化的 ID。
- 暂存配额、过期 ID、非法 ID、额外命令字段和超大请求。
- 重复 Token、其他用户可读的 Token 文件被拒绝。
- 部署帮助进程独立拒绝坏私钥、未知站点和无效 ID。
- 拒绝符号链接 include、外部修改、可写/非 root 拥有的特权配置路径。

### 证书

- 保留完整链；验证域名、信任根、证书/私钥匹配、有效期和链顺序。
- 拒绝缺少中间证书、不受信链、错误域名、过期/未来证书、垃圾数据及多私钥。
- 通配符证书只覆盖实际符合规则的具体域名。
- 中间链指纹会发现链差异，允许自签名信任根的省略。

### 事务与恢复

- 正常提交、相同版本幂等。
- 配置检查、reload、TLS 验证失败后的回退。
- 回退失败时保留 pending 并阻止后续写入。
- 全局并发互斥和跨进程状态锁。
- 中断后恢复旧提交版本。
- 提交文件原子替换之前/之后发生 I/O 错误时，不盲目制造“新状态＋旧配置”；
  两种落盘结果都可一致恢复。

### 真实 Nginx

集成测试通过 HTTPS 接收器和真实 Unix Socket 帮助接口，实际执行：

1. 导入基线并启动隔离 Nginx。
2. 上传新证书，确认尚未改变线上证书。
3. 绑定后通过新 TLS 连接确认新叶子证书与证书链生效。
4. 重复绑定不额外 reload。
5. 注入 Nginx 配置错误，确认旧证书继续提供服务、include 恢复。
6. 让 Nginx 忽略受管理 include，证明“reload 返回成功但仍提供旧证书”会判失败并回退。
7. 构造“新证书已加载、pending 尚未提交”的磁盘状态，重新打开帮助进程，
   对真实 Nginx 执行恢复并确认旧提交版本重新生效。

这些测试使用临时 CA、临时证书和模拟故障，不使用生产私钥。
中断恢复测试模拟持久化状态及帮助进程重建，并非物理断电实验。
